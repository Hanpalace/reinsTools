## 2. 数据连接配置

### 2.1 添加数据库连接

1. 打开「数据批量导入 → 数据连接配置」
2. 点击右上「**新增**」→ 弹窗填写：
   | 字段 | 说明 |
   |---|---|
   | 连接名称 | 自定义标识，如「生产库」 |
   | 数据库类型 | MySQL / PostgreSQL / SQLite |
   | 主机地址 | IP 或域名；SQLite 填数据库文件绝对路径 |
   | 端口 | 切换类型自动填默认值（3306/5432） |
   | 用户名 / 密码 | 数据库账号 |
   | 数据库名 | 目标库 |
3. 点「**测试连接**」验证 → 成功提示后点「**保存**」

### 2.2 日常操作

- **查询**：顶部条件（类型/名称模糊/数据库名）→ 查询/重置
- **编辑**：列表行「编辑」→ 修改后保存（按 id 更新，改名不会产生重复条目）
- **测试联通性**：列表行内按钮，一键复测已保存连接
- **删除**：行内删除（带确认）

> ⚠️ 密码以明文保存在本机配置文件（`%APPDATA%\com.besty.tvta-ui\connections.json`），请勿在多用户共享机器上保存生产库高权限账号。

## 3. 批量导入

### 3.1 标准流程（七步）

1. **选目标连接**：页面顶部下拉选择 MySQL 连接（没有则先去「数据连接配置」添加）
2. **选导入文件**：「选择文件」按钮，可多选 txt/sql 脚本（每行一条 `INSERT INTO ... VALUES (...);` 格式）
3. **配置删除脚本（可选）**：选择文件或粘贴文本（粘贴优先），每行一条 DELETE 语句——用于先清掉旧数据再插入
4. **设置选项**：
   | 选项 | 默认 | 建议 |
   |---|---|---|
   | 每批行数 | 1000 | 保持默认；过大可能导致单条语句超服务器限制而断连 |
   | 单批最大字节(MB) | 1 | 内网/小服务器保持 1~2 |
   | 强制 TLS 加密 | 关 | 远程公网库建议开启 |
   | 临时关闭外键检查 | 关 | 数据量大时开启提速；导入后自行核对完整性 |
   | 剔除自增主键列 | 开 | 脚本携带原始自增主键时保持开启（表之间靠业务键关联的前提） |
5. **开始导入** → 弹出「执行确认」弹窗：
   - **删除影响**：逐条展示删除脚本将影响的行数（dry-run 预演，尚未真正删除）；影响 0 行会自动跳过删除
   - **自增主键处理**：显示将剔除的列
   - **历史导入记录**：若该文件以前成功导入过，会提示确认
   - 确认无误 → 点「**确认执行**」
6. **观察进度**：进度条实时显示 解析 → 删除 → 批量插入（第 N 批/总批数）→ 提交
7. **查看报告**：结果弹窗展示——已提交/已回滚、耗时、文件明细（编码/行数/坏行）、删除行数、每表行数核对（预期/实际/✓）、剔除的自增列

### 3.2 失败怎么办

- **已回滚**：数据不会有任何变化（删除、插入全部撤销），按报告中的失败原因处理：
  - 「第 N 批（源文件第 a-b 行）失败: 重复键…」→ 旧数据未删干净，检查删除脚本覆盖范围
  - 「连接失败/超时」→ 检查网络、VPN、目标库状态
  - 「peer closed connection…」→ 批量语句过大（调小每批行数/字节上限）或网络中断，重试即可
- 修正后直接重跑（失败不会留下脏数据）

### 3.3 历史防重导

同一文件成功导入过后，再次预检会提示「历史导入记录」。这是有意的保护——重复导入会因唯一键冲突回滚，或覆盖式重导线上数据。确认是主动重导再继续。

## 4. 导出批量脚本（内网环境）

当目标环境本软件无法直连时：

1. 选择导入文件（可同时选删除脚本、设选项）
2. 点击「**导出批量脚本**」→ 选择保存位置
3. 导出结果弹窗展示：
   - **单文件**：直接拷贝到内网执行
   - **分片**（文件超过「导出分片上限」时自动切分）：`xxx_part1.sql`、`xxx_part2.sql`…，**按 1→N 顺序依次执行**，每个分片是独立事务

内网执行方式（任一）：

```bash
mysql -u用户名 -p 库名 < 批量导入_part1.sql
mysql -u用户名 -p 库名 < 批量导入_part2.sql
```

或在客户端工具中按顺序逐个执行分片文件。

> 说明：未选择目标连接时导出的脚本**不做自增主键剔除**（无法探测目标表结构），文件头会提示；若脚本携带自增主键且内网库已有数据，请先处理冲突。

## 5. 导入日志与历史

打开「数据批量导入 → 导入日志」。

### 5.1 运行日志

- 自动记录每次预检/导入/导出的关键节点（时间、阶段、结果、耗时、失败原因）
- 「刷新」看最新 500 行；「清空」删除日志文件
- 日志文件位置：`%APPDATA%\com.besty.tvta-ui\import_log.txt`（超过 5MB 自动轮转备份）

### 5.2 导入历史

- **查询**：按结果（成功/失败）、关键字（文件名/说明）、时间范围过滤
- **明细**：每条记录下方浅灰行展示该批次每个文件的名称、行数、表分布
- **手工登记**：内网或其他方式执行的导入，回本机登记留痕（时间/说明/文件明细）
- **编辑 / 删除**：行内操作（删除带确认）
- **重新执行**：一键把该次导入的完整配置（文件、连接、删除脚本、选项）回填到批量导入页并自动预检，确认后重新走完整流程。旧版本台账记录没有配置，「重新执行」置灰

## 6. 常见问题

| 问题 | 处理 |
|---|---|
| 预检报「连接超时（5 秒）」 | 检查网络/VPN；确认主机端口；数据连接配置里先「测试连接」 |
| 导入报「peer closed connection」 | 单批语句过大：把每批行数调回 1000、单批字节 ≤ 1~2MB 后重试 |
| 导入报「重复键冲突」 | 旧数据没删干净：核对删除脚本是否覆盖本次导入的所有合同+账期 |
| 编辑连接改名字后出现两条 | 不会——按稳定 id 更新；若出现请升级到最新版本 |
| 导出脚本在内网报主键冲突 | 导出时未选连接 → 未剔除自增主键列；选用能连通的目标连接再导出，或内网侧先删旧数据 |
| 「重新执行」按钮置灰 | 该记录来自旧版本台账，没有执行配置；新版本执行成功的记录才可重放 |
| 数据文件在哪里 | `%APPDATA%\com.besty.tvta-ui\`：connections.json（连接）、import_history.db（台账）、import_log.txt（日志） |
| 深色模式下表格斑马纹不跟随 | 升级到最新版本（已修复 dark 变体与主题同步） |
| 菜单图标不显示 | 升级到最新版本（已修复 pnpm 下图标加载） |
